# [1.1] test() — coletor de árvore + isolamento por arquivo

`test()` é global e não retorna framework nenhum: só empilha um nó `{ name, fn, op, checks, tests, state, parent }` na árvore.

## Objetivo

`test()` é global e não retorna framework nenhum: só empilha um nó `{ name, fn, op,
checks, tests, state, parent }` na árvore. `utest.js` chama `test.begin(basename)` antes
de `import(arquivo)` e `test.end()` depois, então cada arquivo tem seu próprio root e as
`test()` de topo de um não contaminam o outro.

## Estado atual — 🟡 testada

`test.t.js` cobre árvore aninhada (filho, neto), `op` booleano vs objeto, e o
`_loadingFile` → `address`. Suite verde em 2026-09-03 (2 testes / 14 checks).

## Accomplishments

- Precedência de pai resolvida sem estado global frágil: `this` (dentro de `describe`) →
  `_current` (root do arquivo) → `test.main` (back-compat de `worker.js`).
- `test.begin/end` é o que torna o runner in-process seguro para N arquivos numa passada.

## Debts

- Sem `.eval.js` — o degrau não passa de 🟡 até um roteiro existir (`1.1.eval.js`).
- `test.main` como singleton em `globalThis` ainda é back-compat viva para `worker.js` /
  `index.js`; o caminho de subprocesso depende dela. Ligado a [[7.1]].
- `test.todo` / `test.skip` gravam `op` mas nenhum caminho do runner os honra — um
  `test.skip` roda igual.
