# [6.4] .tuit — snapshot ASCII

`.tuit` é o formato de teste de regressão visual do soml: declarações JSON parciais intercaladas com a arte ASCII esperada.

## Objetivo

`.tuit` é o formato de teste de regressão visual do soml: declarações JSON parciais
intercaladas com a arte ASCII esperada. `kinds.js` já reconhecia o sufixo (scanner +
shim), mas nada executava o arquivo — `tuit.js` é o parser + executor.

## Estado atual — 🟠 implementando

Roda (a suíte do soml tem `.tuit`). **Sem `tuit.t.js`** — o parser de bloco balanceado, o
tratamento de `·`, a regra raiz-nova-vs-parcial (`isFreshRoot`), nenhum tem teste no
utest. → 🟠.

## Accomplishments

- `readBalancedObject` conta `{}` respeitando strings e escapes — um `}` dentro de aspas
  não fecha o objeto cedo.
- A regra de acúmulo (`scl/filelist.tuit`: bloco 1 declara, bloco 2 é só `{ files: [...] }`)
  espelha as primitivas do soml (`_assign` "nunca remove").

## Debts

- **Sem teste próprio no utest.** O executor depende de `pixel`/`soml` globais — testá-lo
  em isolamento exige um mock ou o boot do soml.
- `parseObjectLiteral` usa `Function(...)` — executa o objeto literal do `.tuit` como
  código. OK para arquivo confiável do repo, não para input externo.
- Sem `.eval.js` (`6.4.eval.js`).
