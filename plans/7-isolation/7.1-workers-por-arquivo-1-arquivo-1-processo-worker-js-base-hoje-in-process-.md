# [7.1] worker por arquivo

O isolamento real: 1 arquivo = 1 processo.

## Objetivo

O isolamento real: 1 arquivo = 1 processo. É a única coisa que fecha de vez a atribuição
de exceção assíncrona ao arquivo errado (o `sealed` de [[1.3]] só cobre o `check` tardio,
não a exceção).

## Estado atual — 🟠 implementando (dívida arquitetural aberta)

`worker.js` existe como base (`import './setup.js'` → `loadFile` → `run`), `index.js` o
invoca por arquivo. Mas o caminho ATIVO (`utest.js .`) é in-process — não há orquestrador
de pool, não há `Bun.spawn` por entry no fluxo principal. `HANDOFF.md` descreve um
`orchestrator.js`/`child-worker.js` que **não existe no repo** (foi de uma sessão
anterior, em `~/bot/utest`).

## Accomplishments

- A decisão está tomada e documentada (spawn > Worker, timeout 1s, streaming last-inline).
- `runner.js` + `worker.js` já têm a forma serializável (`serialize()` devolve POJO sem
  `fn`).

## Debts

- **É a maior dívida do repo.** O modelo prometido não está implementado no caminho
  principal.
- `HANDOFF.md`/`TEST-MASTER-PLAN.md` descrevem arquivos (`orchestrator.js`,
  `child-worker.js`, `utils/scanner.js` de zero-dep) que divergem do que está no disco —
  doc velha apontando para código que mudou de casa.
- `STATUS.md` diz "o destino é `cmds/testio/testio.js`" — um terceiro runner, fora deste
  repo. Decidir se o utest ABSORVE o isolamento ou permanece a referência de contrato.
- Sem `.eval.js` (`7.1.eval.js`).
